# Проверка экспериментального VetrOFF-Core Anti-DPI

## 1. Проверка артефакта

Скачайте архив из успешного задания Adaptive Connect candidate ветки Anti-DPI, а не из стабильных Releases. Распакуйте в отдельный каталог Linux amd64. Не заменяйте системное ядро.

```bash
sha256sum -c SHA256SUMS
chmod +x vetroff-core-anti-dpi-linux-amd64
./vetroff-core-anti-dpi-linux-amd64 version
./vetroff-core-anti-dpi-linux-amd64 srun --help
python3 smoke-anti-dpi-cli.py ./vetroff-core-anti-dpi-linux-amd64
```

Последняя команда проверяет обычный локальный прокси, отключённую политику, три ошибочные комбинации параметров и завершение процессов. Реальные подключения к серверам не выполняются.

## 2. Практические проверки на собственном стенде

Подготовьте отдельный конфигурационный файл sing-box для двух собственных тестовых подключений, а также домен тестового HTTPS-сервиса. Не используйте рабочие подписки или настройки с неизвестными параметрами. Экспериментальная интеграция ограничена обычным Selector с двумя или более поддерживаемыми TCP-only leaf-профилями. Для Adaptive MUX отдельно требуется предварительно настроенная и подтверждённая совместимая пара. Физическая диагностика доступна только на Linux при наличии проверенного аппаратного интерфейса и разрешений ОС.

Проверьте по очереди:

| Сценарий | Критерий |
|---|---|
| Обычный запуск | Прежнее поведение при выключенных Anti-DPI опциях |
| Стабильная сеть | Нет неожиданных переключений |
| Плановое отключение собственного тестового сервера | Фиксируется сбой; результат подтверждается по журналам |
| Возврат сервера | Повторные измерения не смешиваются со старыми |
| Смена сети | Старые наблюдения не применяются к новой сети |
| Отмена проверки | Не остаются активные диагностические операции |
| Импорт отчёта | 3x-ui читает версию и показывает исходные результаты |
| Завершение | Процесс останавливается, локальные ресурсы освобождаются |

Сохраняйте дату, версию ядра, тип сети, наблюдаемую ошибку, результаты TCP/TLS/HTTPS и факт завершения сценария. Не публикуйте UUID, пароли, приватные ключи, токены, ссылки подписок и необработанные журналы. При сбоях остановите экспериментальный процесс и вернитесь к отдельно установленной стабильной версии.

## 3. Границы проверки

Успешный CI и локальный smoke-тест не подтверждают доступность VPN у конкретного мобильного оператора, наличие белого списка IP или отсутствие ограничений. Для практических результатов нужны измерения на реальном оборудовании и собственных серверах. Отчёты физического пути и VPN сопоставляйте только в близких условиях и на одной версии ядра. Не меняйте рабочую конфигурацию автоматически по результату одного измерения.
